# 手机端杠杆部分平仓弹窗与双滑杆确认

## 背景

手机端杠杆持仓卡片目前通过按钮二次点击直接平仓，没有实现 Pencil 当前选中的平仓底部弹窗，也缺少防误触的拖动确认交互。

## 目标

1. 普通“平仓”从持仓卡片打开底部弹窗，不再在卡片内二次点击提交。
2. 弹窗按 Pencil 当前选中的浅色 `ajSJF` 与深色 `DGiNR` 设计实现：遮罩、500px 底部面板、标题与关闭按钮、仓位摘要、市场价格、可调平仓比例轨道、持仓数据和底部粉色确认区域。
3. `margin-close-sheet__ratio` 是 1% 到 100% 的真实拖动条，支持连续选择部分平仓比例，并同步更新可平数量和预计收益。
4. 底部确认区域支持从左向右拖动；只有达到确认阈值才按冻结的仓位、比例和幂等键提交一次部分平仓请求。
5. 拖动未达到阈值、取消、Escape、遮罩关闭、请求失败或目标仓位消失时恢复确认滑块，不产生重复结算。
6. 支持鼠标、触摸、触控笔、键盘和减少动态效果；弹窗具备焦点闭环、滚动锁与焦点恢复。

## 业务边界

- 单仓平仓接口新增可选 `percentage` 与 `idempotency_key`；不带请求体的历史调用仍按 100% 全平兼容。
- 显式比例请求必须是 1..=100 的整数百分比并带幂等键。同键同仓位同比例只重放一次；同键异参返回冲突。
- 部分平仓按当前剩余仓位的保证金、名义价值、借款和利息同比例结算，仓位保持 opened；100% 或最后剩余份额才进入 closed。
- 钱包、流水、部分平仓执行记录与仓位剩余金额必须在同一事务提交，结算价格只取服务端权威标记价。
- 弹窗里的数量和预计收益来自当前仓位及服务端风险快照；缺失时显示 `--`，不得填入样例数据。
- “市价全平”快捷按钮保留既有独立二次确认；顶部批量平仓逻辑保持不变。
- 最终请求复用扩展后的 `closeMarginPosition(position.id, intent)`，成功后重新对账钱包、仓位及风险快照；私有 WebSocket 事件只作为加速 REST 对账的提示。

## 验收标准

- [x] 普通平仓按钮只打开弹窗，打开时未发出平仓请求。
- [x] 浅色/深色面板关键几何与 Pencil 一致：宽度占满、顶部圆角 24px、内容左右 20px、主字段 58px、比例轨道 24px、确认轨道 62px。
- [x] `margin-close-sheet__ratio` 可在真触控、鼠标和键盘下连续拖动 1%..100%，显示百分比、可平量与比例预计收益同步变化。
- [x] 只有底部圆形确认手柄越过阈值才提交；点按确认轨道不提交，未越过阈值释放会回弹。
- [x] 50% 逐仓/全仓平仓只结算对应份额、保留剩余仓位；100% 兼容旧全平行为。
- [x] 同一幂等键重试不重复入账、流水或执行记录；同键异仓位/异比例冲突。
- [x] 提交中锁定比例、关闭与再次拖动；成功关闭弹窗并刷新，失败保留比例与幂等键、确认滑块回弹并显示错误。
- [x] Escape/遮罩/关闭按钮在非提交状态可关闭；Tab 焦点闭环并恢复至来源按钮。
- [x] 所有新增固定文案具有中英文 i18n，不使用表情符号，图标继续使用 Lucide。
- [x] 聚焦后端测试、迁移测试、Mobile 全量测试、type-check、PWA 构建、架构测试与 `git diff --check` 通过。
