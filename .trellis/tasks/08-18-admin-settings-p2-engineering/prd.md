# P2 后台设置工程与交互体验统一

## Goal

将重复的设置加载、编辑、脏状态、差异确认和提交流程收敛为共享工程能力，提升审计可读性并清理重复实现。

## Requirements

- 建立共享设置编辑壳与 hooks，统一 React Query 加载、mutation、缓存失效、错误和重试。
- 以共享字段 schema 描述中文标签、值格式、校验和影响文案，减少页面重复校验与错误映射。
- 共享脏状态管理同时阻止路由离开、刷新/关闭和意外覆盖。
- 确认流程展示中文字段差异、影响摘要和原因，高风险动作与普通保存有明确视觉语义。
- 审计页提供中文动作、字段级差异、对象跳转、时间范围和脱敏导出。
- SMTP、行情策略、预测配置等大页拆成领域组件/hooks，清理孤立 `ProductStatusActions` 和重复包装页。
- 敏感配置只展示轮换/验证元数据，不回显明文。

## Acceptance Criteria

- [x] 首批单例配置页使用共享编辑壳，加载、冲突、错误、脏状态和成功状态有测试。
- [x] 存在未保存变更时，站内导航与浏览器离开均有明确中文确认。
- [x] 审计详情不依赖管理员阅读原始 JSON 就能识别字段变化。
- [x] 审计导出沿用当前筛选并确保敏感字段在写入 CSV 前已脱敏。
- [x] 重复/孤立页面不再出现于可达路由，兼容 URL 只做重定向。
- [x] 大页文件尺寸和责任明显收敛，现有 API 请求与业务功能无回归。
