# 杠杆产品后台现状与业务流程调研

## 数据流

`后台表单 -> POST/PATCH /admin/api/v1/margin/products -> product_config 校验与归一化 -> margin_products -> 用户端产品列表/开仓`

## 已确认事实

- 后端能力包声明 `margin_modes=["isolated", "cross"]`，用户开仓与账户设置都会校验所选模式必须同时存在于产品的 `margin_modes`。
- 产品的 `margin_mode` 是默认模式，后端实际以 `margin_modes` 的第一个元素生成该字段；因此后台必须显式管理默认模式并保证它排在提交数组首位。
- 当前后台把“支持保证金模式”渲染为只读文本“逐仓”，编辑回填时会丢弃 `cross`，提交时又硬编码 `margin_modes: ["isolated"]`。编辑一个支持全仓的产品会静默降级为仅逐仓。
- 杠杆档位必须非空、每档大于 1、去重，`max_leverage` 必须等于最大档位；当前后台会静默丢弃非法自定义档位，缺少明确反馈。
- 风控字段契约为：最小保证金必须为正数；最大保证金可空，否则必须为正且不小于最小值；维持保证金率和小时利率必须为非负十进制数。
- 产品停用只阻止新开仓；既有仓位仍可平仓并继续计息。修改产品参数只影响后续开仓，不重写已有仓位快照。
- 创建与编辑已经复用同一字段组件和三个 Tab，但没有步骤完成状态、前后步骤导航或提交前业务摘要。

## 可行方案

### A. 单选保证金模式

只提供“逐仓/全仓”单选下拉，每个产品仅支持一种模式。实现简单，但会浪费后端已经支持的多模式产品能力，也无法表达“同时支持两种、默认其中一种”。

### B. 支持模式多选 + 默认模式单选（采用）

“支持保证金模式”使用多选下拉，“默认保证金模式”使用单选下拉且只能从已支持模式中选择。提交时将默认模式放到 `margin_modes` 首位，并同时发送 `margin_mode`，兼容现有后端语义。该方案完整覆盖后端能力，且不会让数组顺序成为管理员不可见的隐式配置。

### C. 从列表响应动态注入能力

由资源页把 `capabilities` 原样传入创建和编辑动作，再动态生成模式选项。扩展性最佳，但当前 `AdminResourcePage` 的 actions/rowActions 只接收 reload、record 等参数，需要扩大通用资源页接口。现阶段后端能力只包含稳定的 `isolated/cross`，为两个枚举值改动通用资源页收益不足。

## 本次收敛范围

- 采用方案 B。
- 保留现有 API 和数据库结构，不修改用户端下单页面。
- 把现有三段配置扩展为“基础配置 -> 杠杆档位 -> 风控与计费 -> 发布确认”的四步流程。
- 增加前端完整性校验、错误提示、步骤导航和发布摘要；后端仍是最终业务校验边界。
- 列表新增“默认保证金模式”列，避免管理员只能看到支持集合、看不到默认行为。

## 关键边界

- 已选默认模式被移除时，自动回落到剩余支持模式的第一项；全部移除时默认模式清空并禁止进入发布。
- 历史记录缺少 `margin_modes` 时使用 `margin_mode` 回填；两者都缺失时兼容为逐仓。
- 自定义档位中任一非数字或不大于 1 的值都会阻止下一步，不能继续静默丢弃。
- 最大保证金为空代表不设上限；有值时必须大于等于最小保证金。
- 发布确认明确提示：启用状态会立即允许新开仓；配置变更不影响既有仓位。
