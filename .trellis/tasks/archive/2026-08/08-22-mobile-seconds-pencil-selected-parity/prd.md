# 手机端秒合约按 Pencil 当前选稿 1:1 重构

## Goal

以用户当前在 Pencil 中同时选中的浅色 `VL8er` 与深色 `g9agt` 为唯一视觉基线，重新实现生产手机端 `/seconds` 秒合约交易页面，使 390px 基准下的页面结构、几何、排版、色彩、密度和交互层级与选稿逐项对应，同时完整保留真实行情、真实账户、真实下单、并行活动订单、结算提示与历史订单闭环。

## What I already know

- 用户明确要求依据 Pencil 当前选中页面 1:1 重新实现，不沿用未选中的旧版本或自行改稿。
- 当前选中的是同一页面的浅色/深色两张 390 × 920 画板：`VL8er`、`g9agt`。
- `/seconds` 已经存在产品、周期、行情/K 线、钱包、确认下单、并行活动订单、结算结果提示和独立 `/seconds/history` 页面；本次是生产页面视觉重构，不把原型示例数据复制到真实业务。
- 现有固定要求包括 Lucide 图标、`zh-CN`/`en` 双语、明暗主题、PWA/Tauri 构建、320–448px 无横向溢出、44px 触控语义和减少动态效果支持。

## Requirements

### 1. 选稿与结构

- 页面根节点记录 `data-pencil-source="VL8er/g9agt"`。
- 390px 基准按画板实现 28px 系统安全区轨道、60px 页面 Header、420px 交易操作区和从 y=508 开始的进行中订单区；Web/PWA 不重复渲染原生状态栏内容。
- Header 使用左返回、绝对居中的交易对/“秒合约”标签/下拉箭头、右历史三轨结构；返回逻辑沿用安全回退，历史按钮进入命名路由 `seconds-history`。
- 页面不挂载 RootHeader 或底部 Dock，不改变 `/seconds` 的二级路由层级。

### 2. 行情与图表

- 顶部按选稿的同一轨道展示真实订单/交易状态与可用倒计时、收益率、实时最新价、实时涨跌/参考价和行情状态。后端没有全局轮次编号时不得伪造 `01842`，可用最近活动订单 ID/倒计时或本地化待下单状态占据相同几何。
- 图表保持选稿 112px 视觉高度、四条网格线、绿色折线、末端实时点与光晕；继续使用现有真实 K 线及行情流，晚到 REST 不得覆盖新实时帧。
- 加载、暂无行情、断线重连和错误状态必须保持选稿区域几何，不使用 `63,085.00` 等画板样例值。

### 3. 下单表单

- 周期选项为画板的一行四项密度；选项内容、最低/最高金额和选中态来自当前真实产品周期，周期数量超出四项时必须仍可访问且不造成页面横向溢出。
- 显示当前周期动态限额条，金额输入采用选稿左右标签/数值结构，并继续执行正数、余额、产品上下限和精度校验。
- 买涨/买跌采用两枚 40px 视觉分段控件，分别使用绿色/珊瑚红语义，明确选中状态与 ARIA 状态。
- 主操作为 44px 绿色按钮，动态显示方向、金额与结算资产；游客跳转登录，已登录用户继续走现有确认弹层和真实 API。
- 提交期间保持幂等、防重复触发和确认快照；创建响应成功后立即写入活动订单，刷新失败不能回滚成功或重新开放重复提交。

### 4. 活动订单工作区

- 标题、订单总数、命名历史入口以及“全部/买涨/买跌”三项筛选与选稿一致。
- 每张活动订单卡呈现后台交易对 Logo、交易对、方向、倒计时、金额、入场价、预计净收益和进度条；缺失 Logo 使用共享 `AssetMark` 回退，不绘制假 Logo。
- 卡片视觉在 390px 基准为 350 × 82、12px 圆角、1px 主题描边；更多订单允许页面自然纵向延长，不能把第 4 张及后续订单裁掉。
- 筛选只改变本地活动订单显示，不改服务端订单；结算后的订单应从活动区移除并继续进入现有结算通知队列。
- 空订单、加载、游客和失败状态均使用真实状态，不伪造三张演示订单。

### 5. 主题、排版与交互

- 浅色严格使用 `#FFFFFF / #111714 / #68736D / #DDE4E0 / #D9F9EB / #087B52` 与信号绿 `#43EFA9`、跌色 `#FF654A`；深色严格使用 `#000000 / #050806 / #0C100E / #F2F7F4 / #95A19A / #202923 / #103326 / #61F1B6` 与同一信号绿/跌色。
- 字体层级以画板 Geist、Geist Mono、Inter 为准；固定文案全部来自 i18n。
- 仅使用 Lucide 图标，不使用表情符号或第二套图标库。
- 视觉高度低于 44px 的期限/筛选轨道通过外层或伪元素扩充触控范围；焦点环、禁用态、忙碌态、ARIA 标签/状态和减少动态效果完整可用。
- 320 × 720、390 × 844/920、448 × 900 明暗主题均无横向溢出，安全区、键盘与短视口下不裁切主操作或确认弹层。

### 6. 现有业务闭环保留

- 继续使用真实公开产品、实时行情/K 线、钱包、下单和订单列表接口。
- 保留交易对选择、确认下单、并行订单、每 1 秒倒计时、服务端对账、私有结算刷新、输赢非模态提示、独立历史页和登录/退出会话隔离。
- 预计收益继续严格等于 `stakeAmount × payoutRate`，不重复计入本金；价格、轮次、赔率、限额、余额和订单结果不由前端猜测。

- 测试先行：先补充会失败的选稿几何、主题、结构、数据真实性和交互合同，再实现通过。
- 不覆盖当前工作区与本任务无关的手工修改。
- 更新 Mobile 可执行规范与 `docs/superpowers/PROGRESS.md`。
- 完成代码复核、类型检查、全量测试、PWA/Tauri 构建和真实浏览器多尺寸验收。

## Technical Approach

1. 以 Pencil MCP 导出的浅/深参考图和节点规格为视觉真值，建立源码/运行时合同测试。
2. 保留 `SecondsView.vue` 已有响应式状态、API、行情和订单生命周期，重组模板为 Header、市场摘要、图表、下单参数、活动订单工作区五个明确区域；仅在重复结构确实需要时抽取小组件/纯展示函数。
3. 复用共享 `AssetMark`、`PageHeader` 的安全回退思想、现有秒合约 DTO/追踪器/确认弹层，不复制或改写业务规则。
4. 主题令牌放在项目允许的全局选中页样式层，页面 scoped CSS 只管理路由局部布局；验证既有全局选择器不会覆盖选稿几何。
5. 使用真实浏览器计算样式与边界框对照 Pencil 规格，针对 320/448px 只做必要的流式收敛，不改变 390px 基准。

## Decision (ADR-lite)

**Context**：当前页面功能已较完整，但视觉实现未以用户当前选稿为唯一真值；完全新建业务页面会增加实时行情、对账和结算回归风险。

**Decision**：采用“保留现有业务状态机与接口、重构模板和主题层”的方式。Pencil 控制视觉，现有生产契约控制数据与业务；不把设计稿静态示例写入运行时。

**Consequences**：视觉层会有较大模板/CSS改动，但后端和核心订单语义保持稳定；需用源码合同、行为测试和浏览器几何三层验证，避免仅凭截图通过。
