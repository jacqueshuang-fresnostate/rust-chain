# 手机资金账单补齐杠杆账户流水

## 背景

手机端 `/assets/ledger` 当前只请求 `GET /api/v1/wallet/ledger`，而后端该接口只查询 `wallet_ledger`。杠杆账户转入、开仓、平仓、取消和强平等资金变动主要记录在 `margin_wallet_ledger`，因此用户在“资金账单”中看不到完整的杠杆账户流水。

## 目标

- 让资金账单默认同时展示现货账户和杠杆账户流水。
- 让用户可以按账户类型筛选“全部 / 现货 / 杠杆”，并在每条记录上看到明确的账户来源。
- 保留现有业务分类、精确变动类型、时间和其他筛选的兼容性。
- 保证合并后的分页、总数、排序和行身份稳定可预期。

## 已确认的现状

- 现货账户流水存储在 `wallet_ledger`。
- 杠杆账户流水存储在 `margin_wallet_ledger`。
- 现货与杠杆的转账会在两张流水表中各写入一笔对应记录；合并展示时必须标明账户来源，不把对应记录误判为重复数据。
- 两张表的数字 `id` 可能相同，手机端不能仅用 `id` 作为合并后的唯一标识。
- 现有 `category=margin` 表示业务分类，不等于账户类型；两者需要保持独立。

## 后端需求

1. `GET /api/v1/wallet/ledger` 合并读取 `wallet_ledger` 和 `margin_wallet_ledger`。
2. 每条响应增加 `account_type`，仅允许 `spot` 或 `margin`。
3. 新增可选查询参数 `account_type`，允许 `all`/`spot`/`margin`；省略时等价于 `all`。
4. 在取得数据库连接前完成 `account_type` 白名单校验，非法值返回 HTTP 400。
5. 列表查询与 COUNT 查询共用同一组账户及业务筛选语义，避免总数与实际页内数据不一致。
6. 合并结果按 `created_at DESC`、账户类型和 `id DESC` 进行稳定排序，再应用 `limit/offset`。
7. 保持所有 DECIMAL 字段的字符串精度、币种 Logo、手续费关联和现有业务分类规则。
8. 本次只读取已有流水，不修改资金写入路径，不新增或修改数据库迁移。

## 手机端需求

1. 账单模型映射并保留后端 `account_type`，非法值按合同错误处理，不猜测账户来源。
2. 接口请求支持传递 `account_type`，账单页默认请求 `all`。
3. 账单页新增“全部 / 现货 / 杠杆”账户切换，与现有业务分类独立组合。
4. 每条账单显示账户来源标签，中英文 i18n 对称。现有业务分类 `margin` 的文案使用“杠杆 / Margin”，不写成“合约 / Futures”。
5. 切换账户或业务分类时重置分页；忽略过期请求，避免快速切换后被旧响应覆盖。
6. 缓存合并和 Vue DOM key 使用 `accountType:id` 复合身份，不丢失两张表中数字 ID 相同的记录。
7. 保持现有日期分组、加载/空/错误状态、载入更多和 44px 可点击区域。

## 验收标准

- 一个同时拥有现货和杠杆流水的用户打开资金账单时，默认列表可看到两种账户记录。
- 选择“现货”只显示 `wallet_ledger`；选择“杠杆”只显示 `margin_wallet_ledger`。
- 账户筛选与 `category`/`change_type` 等现有筛选可组合，列表行数和 `total` 一致。
- 两张表各有一条相同数字 ID 的流水时，两条都被显示且不会相互覆盖。
- 合并列表在同一时间戳和翻页边界下仍保持确定性。
- 非法 `account_type` 在无数据库状态下仍稳定返回 400。
- 后端定向单元/路由测试、手机端账单分类测试、类型检查和构建通过。

## 非目标

- 不回填或重算历史流水。
- 不更改杠杆交易、转账、平仓或强平的资金结算逻辑。
- 不调整 PC 端或管理后台的账单页。
- 不增加导出、新的金额统计或账户间抵销逻辑。

## 验证计划

- Rust：分类/账户参数解析、共享查询谓词、联合排序、响应映射、路由 400 和数据库集成用例。
- Mobile：DTO 映射、复合身份合并、账户/业务组合筛选、过期响应、i18n 对称与页面源码合同。
- 工程：`cargo fmt --all -- --check`、定向 `cargo test`、Mobile 定向/全量测试、`type-check`、构建以及 `git diff --check`。
