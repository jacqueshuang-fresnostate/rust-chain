# 修复全仓双向强平记账与预估强平价

## Goal

修复同一结算资产下同时存在全仓做多与做空时的账户级强平：强平不得因为逐仓式逐笔返还或符号错误增加杠杆钱包余额，并按业务要求消耗该全仓账户可用抵押资金；同时让手机端持仓卡显示由后端权威风险快照计算的全仓预估强平价。

## What I already know

- 用户实测全仓同时做多与做空触发强平后，杠杆钱包金额反而增加；预期是该全仓账户抵押资金被全部扣除。
- 全仓风险范围是 `(user_id, margin_asset)`，同一结算资产的已成交持仓必须作为一个账户整体判定和处置。
- 当前后端规范明确把全仓 `estimated_liquidation_price` 和 `liquidation_distance_rate` 返回为 `null`，手机端据此显示“账户级风控”，因此第二个问题不是单纯样式缺失，而是接口契约尚未提供可展示值。
- 已有 worker、结算基础设施、风险查询 DTO 和手机端风险映射可复用，不新增平行资金系统。
- 既有未跟踪目录 `mobile/pencil/docs/` 与本任务无关，必须保留且不纳入改动。

## Assumptions (temporary)

- “全扣”指账户级强平成功后，该 `(user_id, margin_asset)` 的可用杠杆钱包抵押余额不得获得任何仓位返还，并按强平业务规则归零；不得误改现货钱包或其他结算资产钱包。
- 全仓预估强平价按“同一全仓账户、同一交易标的的所有已成交仓位同步变价，其他标的维持当前标记价”的账户级情景求解；同一标的净方向数量为零时不存在有限价格阈值，返回 `null` 并展示明确文案。
- 强平与钱包、流水、仓位、强平记录、cross account 快照继续在一个数据库事务内提交并保持重试幂等。

## Open Questions

- 无需用户补充即可先从现有记账模型、数据库字段和测试推导；若代码证明“全扣”与现有冻结/挂单资金语义冲突，再收敛为只清零权威可用抵押桶并明确记录其他桶处理。

## Requirements

- 找到并修复全仓账户强平中造成余额增加的逐笔返还、重复入账或 PnL 符号问题。
- 账户级强平只执行一次钱包结算；每个仓位只更新状态、实现盈亏、强平记录和事件，不再各自向钱包返还保证金。
- 强平结算金额必须非负且不超过事务锁定后的权威全仓钱包可用余额；按业务要求处置后该账户可用抵押余额为零。
- 同一全仓账户的多空持仓必须全部终结；重试、并发 worker 或部分已终结仓位不得再次扣款、返款或重复写流水。
- 强平流水使用账户级引用和唯一语义，能审计强平前余额、扣除额与强平后余额。
- 本次按产品既定“全扣”语义处理：账户触发全仓强平后，将事务锁定的 `margin_wallet_accounts.available` 一次性扣到零；流水金额等于 `-available_before`，仓位 `payout_amount` 全部为零。`frozen`/`locked` 桶、其他资产和现货钱包不在本次扣除范围内。
- 全仓坏账按强平前账户总权益 `equity` 的负值部分计算，即 `max(-equity, 0)`；正剩余权益作为强平损失被消费，不再回流用户钱包。本次不新增保险基金或平台对手账。
- 后端风险接口为全仓持仓返回可求解的账户级预估强平价和距离；同一标的净数量为零、非正结果、缺行情或不可求解时返回 `null`。
- 全仓预估价格必须考虑同一结算资产下所有已成交全仓持仓的保证金、未实现盈亏、利息、维持保证金和同标的净方向风险，不能退化为单仓逐仓公式。
- 手机端优先显示服务端全仓预估强平价；只有接口明确为不可求解时才显示账户级/无有限阈值文案，不在客户端伪造账户公式。
- 保持现有顶层逐仓风险字段兼容；在现有风险响应内新增可选 `cross_account_risk`，承载账户权益、维持保证金、缓冲、同标的净/总数量、估算状态、条件强平价与距离。全仓手机展示以该对象为权威。
- 保持逐仓强平、正常单仓平仓、挂单撤销、现货钱包和其他资产不受影响。

## Acceptance Criteria

- [x] 全仓同资产同时存在做多与做空，触发账户强平后杠杆钱包可用余额不会增加，并按业务规则变为零。
- [x] 所有属于该账户的已成交全仓持仓一次性变为 `liquidated`，每仓位都有正确 realized PnL/强平记录，但钱包只出现一条账户级强平流水。
- [x] 重复运行 worker 不再改变余额、流水和仓位终态。
- [x] 全仓单方向或非完全对冲仓位的风险接口返回有限正数预估强平价与距离。
- [x] 同标的完全对冲导致净方向数量为零时返回 `null`，手机端显示明确不可求解状态，不显示伪造价格。
- [x] 多标的全仓账户按目标标的情景计算，其他标的使用同一风险快照的当前标记价。
- [x] 逐仓风险与强平回归测试保持通过。
- [x] Rust 格式、检查、Clippy、聚焦/全量测试及 Mobile 类型检查、测试、PWA 构建通过。

## Decision (ADR-lite)

**Context**: 逐仓可以对单个仓位求强平价并把剩余权益返还原钱包；全仓共享钱包权益，若逐仓式逐笔结算会重复返还或把一边盈利错误计入钱包。

**Decision**: 全仓强平采用“仓位明细终结 + 一次账户级钱包清算”模型。预估强平价采用同一账户中目标标的的净方向情景求根，其他标的按当前 mark 固定；完全对冲无有限根时返回空值。

账户级条件强平价使用当前引擎的静态名义价值维持保证金口径。令当前缓冲 `B = equity - maintenance_margin`，目标交易对净数量 `D = Σ(sign × notional / entry)`，则候选价为 `P* = current_mark - B / D`。只有 `B > 0`、净数量不是零/近零、结果为正且位于净敞口不利方向时才返回；否则以稳定状态码说明原因。所有同交易对仓位共用同一份 Redis 行情快照，其他交易对保持各自当前 mark。

**Consequences**: 钱包记账有单一所有者并可幂等审计；全仓持仓可以显示有业务意义的价格阈值，同时不会为零净敞口伪造数字。

## Out of Scope

- 新增保险基金、穿仓分摊、自动减仓或资金费率系统。
- 修改普通用户主动平仓的剩余权益返还规则。
- 改变逐仓预估强平公式或现货/秒合约钱包记账。
- 为多种结算资产计算统一折算后的组合保证金。
