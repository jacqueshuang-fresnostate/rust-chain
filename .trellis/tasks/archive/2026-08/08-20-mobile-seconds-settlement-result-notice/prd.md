# 手机端秒合约结算输赢提示

## Goal

当用户停留在手机端 `/seconds` 交易页且活动订单被后端确认结算后，立即展示清晰、可信且不阻断继续交易的输赢提示，避免订单从活动列表消失后用户不知道最终结果。

## Requirements

- 只在本次页面会话中曾被观察为活动状态的订单由后端订单接口返回 `result = win|loss` 时提示；首次进入页面不得为历史订单补弹旧结果。
- 输赢必须来自后端最终订单快照，不得使用客户端倒计时、实时价格或本地比较提前推断。
- 赢单展示“结算盈利”、带 `+` 的净盈利 `stakeAmount × payoutRate` 和订单结算资产；输单展示“结算亏损”、负本金 `-stakeAmount` 和订单结算资产。
- 提示展示交易对、看涨/看跌方向和期限，用户可关闭当前提示、继续交易或进入秒合约历史订单页面。
- 多个订单在同一次对账中结算时必须逐笔排队展示，并告知剩余结果数量；同一订单在重复轮询、重试或返回顺序变化时只能提示一次。
- 订单先返回非活动但暂缺结果、后续再返回 `win|loss` 时仍可提示；取消订单不显示输赢提示。
- 结果提示使用非模态悬浮卡，不锁定页面滚动、不阻断其他订单和下单表单；卡片使用 Lucide 图标、毛玻璃层次、明暗主题语义色和至少 44px 操作目标。
- 新文案同时提供简体中文和英文，模板不得写死用户可见中英文文本。
- 组件卸载、退出登录或私有状态清空时清理追踪器与待展示队列，不把结果跨账号或跨页面泄漏。

## Technical Approach

在 `mobile/src/core/secondsOrder.ts` 增加页面会话级结算提示追踪器：先记录被观察到的活动订单 ID，再从后续权威订单列表中提取首次出现的 `win|loss` 终态，按到期时间排序并做会话内去重。`SecondsView.vue` 继续沿用现有到期轮询与 `applyReconciledOrders()` 对账入口，将追踪器返回的订单加入 FIFO 展示队列，并复用 `secondsOrderProfitLossPresentation()` 计算净盈亏。结果 UI 使用 Teleport 的非模态毛玻璃悬浮卡，不新增后端接口或客户端价格判定。

## Decision (ADR-lite)

**Context**：秒合约页面已有每秒倒计时和到期后订单/钱包并行对账，但订单从活动区消失时没有结果反馈；页面允许多个并行订单，因此单个临时字符串无法表达并发结算。

**Decision**：使用“权威订单状态转换追踪器 + FIFO 非模态结果卡”。只追踪本页看到的活动订单，首次历史加载只建立基线；结果卡由用户关闭或继续交易推进，查看历史会清空队列并跳转。

**Consequences**：不会为旧历史订单或本地推测结果误报，重复轮询不会重复弹出，多单结算不会丢失；提示不锁滚动，仍可继续下单。页面卸载后队列不持久化，重新进入不会重放旧结果。

## Out of Scope

- 不修改后端结算、钱包入账、数据库或订单 API 响应。
- 不增加声音、震动、系统推送或跨路由持久通知。
- 不修改秒合约历史列表的盈亏口径和现有下单确认弹窗。

## Technical Notes

- 后端 `SecondsContractOrderResponse` 明确约定 `status = settled` 且 `result = win|loss`，列表按创建时间倒序返回。
- 现有 `reconcilePrivateState()` 在到期后同时刷新订单与钱包；`applyReconciledOrders()` 是订单快照进入页面的单一入口。
- `secondsOrderProfitLossPresentation()` 已提供赢单净收益、输单负本金和语义色，结果提示必须复用该口径。
- 详细数据流见 [`research/settlement-notice-flow.md`](research/settlement-notice-flow.md)。
