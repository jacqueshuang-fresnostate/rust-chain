# 修复手机端闪兑方向调换无响应

## 背景

手机端 `/swap` 的上下调换按钮只会在 `GET /convert/pairs` 同时返回一条显式反向配置时切换。后端实际上允许同一条闪兑配置按正反两个方向报价，并通过 `target_min_amount/target_max_amount` 提供反向限额；列表只返回配置原始方向时，当前前端找不到反向行，因此点击按钮没有任何可见变化。

## 要求

1. `GET /convert/pairs` 的每条启用配置必须投影为可选择的正向和反向方向。
2. 若后端显式返回反向配置，该显式配置优先，不得再用另一条配置生成的反向投影覆盖。
3. 反向方向交换资产 ID、symbol 和 Logo，并使用 `target_min_amount/target_max_amount` 作为源金额限制。
4. 前端选择状态必须同时区分配置 ID 和资产方向；同一配置的正反方向不能因共享 ID 而回落到第一项。
5. 点击调换后立即清空旧报价、错误和成功提示，保留当前输入金额，让用户看到支付/接收资产、Logo、余额、最小值与费率方向立即更新。
6. 报价请求继续只发送真实 `from_asset_id`、`to_asset_id` 和 `from_amount`；不得发送客户端方向键或伪造配置 ID。
7. 交易对选择器继续优先保留当前对手资产，并能选择投影出的方向。
8. 无有效反向方向时按钮保持确定性，不产生错误状态或伪造数据。

## 验收标准

- 单条 BTC→USDT 配置可切换为 USDT→BTC，第二次点击恢复 BTC→USDT。
- 反向使用目标侧限额和交换后的后台 Logo；可用余额跟随新的支付资产。
- 同时存在 BTC→USDT 与 USDT→BTC 显式配置时，各方向使用对应显式配置。
- 调换后旧 quote/error/success 清空，amount 保留。
- 聚焦测试、Mobile 类型检查与全量测试通过；Ego Browser 点击验证可见方向变化且无横向溢出。

## 范围外

- 不修改后端闪兑撮合、报价或结算语义。
- 不修改当前未提交的杠杆页面改动。
- 不纳入既有未跟踪目录 `mobile/pencil/docs/`。
