# 修复手机端杠杆持仓风险指标缺失

## 背景

手机端 `/trade/:symbol` 的杠杆持仓卡片已经预留“维持保证金率”和“预估强平价”，但当前展示逻辑存在两个问题：

1. “维持保证金率”错误读取了 `margin_ratio`（账户/仓位权益除以维持保证金），而不是产品配置及风险快照里的 `maintenance_margin_rate`。
2. “预估强平价”完全依赖即时风险请求；行情缓存短暂不可用或风险请求失败时，逐仓仓位即使具备完整静态参数也只显示 `--`。

后端现有风险接口已定义：逐仓返回单仓预估强平价；全仓因为按共享账户风控，不返回伪造的单仓强平价。

## 目标

- 杠杆持仓卡片始终以正确口径展示维持保证金率。
- 逐仓持仓优先显示后端风险快照返回的预估强平价；即时风险请求暂时失败时，使用与后端领域公式一致的、基于仓位与当前产品配置的展示回退值。
- 全仓持仓明确显示“账户级风控”语义，不伪造单仓强平价格。
- 保持风险快照对标记价、浮动盈亏、收益率、保证金率和强平距离的权威性；回退只用于本任务指定的两个字段。

## 功能要求

### 1. 维持保证金率

- 优先使用该仓位最新风险快照的 `maintenanceMarginRate`。
- 风险快照缺失时，回退使用对应 `MarginProduct.maintenanceMarginRate`。
- 仅接受有限且非负的数值；无有效值才显示 `--`。
- 不再把 `marginRatio` 展示为“维持保证金率”。

### 2. 预估强平价

- 后端风险快照存在有效正数时，直接使用后端值。
- 逐仓仓位的快照值缺失时，按后端同源公式计算展示回退：
  - `maintenance = notionalAmount * maintenanceMarginRate`
  - `adjustment = (maintenance - marginAmount + interestAmount) / notionalAmount`
  - 多仓：`entryPrice * (1 + adjustment)`
  - 空仓：`entryPrice * (1 - adjustment)`
- 回退计算必须校验入场价、名义价值、保证金、利息和维持保证金率；结果不是有限正数时返回空值，不制造 `0`。
- 全仓仓位不执行单仓公式，显示本地化的“账户级风控”说明。

### 3. 展示与兼容

- 中文与英文文案都必须补齐。
- 保持当前 Pencil 杠杆持仓卡片结构、主题和操作逻辑，不重排无关区域。
- 风险请求失败不能移除仓位，也不能覆盖已经成功取得的其他仓位快照。
- 不改变后端风险、强平或结算行为，不增加资金写操作。

## 验收标准

- 风险快照包含值时，卡片显示后端维持保证金率和预估强平价。
- 风险快照缺失时，维持保证金率仍由产品配置显示。
- 逐仓风险快照缺失时，预估强平价按后端同源公式显示。
- 全仓仓位显示账户级风控文案而不是单仓数字或含义不明的 `--`。
- 单元测试覆盖多仓、空仓、服务端优先、产品回退、全仓和非法输入。
- `npm --prefix mobile run type-check` 与相关移动端测试通过。

## 非目标

- 不改变后端强平公式、强平 worker 或全仓账户风险模型。
- 不在订单历史页面为已结束仓位伪造实时风险指标。
- 不调整杠杆下单、平仓、余额或行情刷新流程。
