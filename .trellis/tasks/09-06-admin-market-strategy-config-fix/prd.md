# 修复后台行情策略配置

## Goal

检查并修复管理员行情策略的读取、编辑、预设、预览及保存操作，保持现有后端不可变版本、启用限制及确定性生成合同。

## Known context

- 用户反馈行情策略配置仍有问题，尚未提供具体操作或报错；已请求补充，同时先检查现有实现。
- 主入口为 `/admin/market/strategies`，表单复用 `marketStrategy` actions/model 与节点编辑器。
- 当前工作树已有 Mobile 新币记录页面改动，完全保留。

## Plan

1. 对照后端合同检查配置读写和状态限制，先增加能复现问题的测试。
2. 只修复确认的行情策略配置缺陷，补齐明确的中文校验反馈。
3. 执行聚焦与 Web 质量验证，更新规范和进度；不操作真实行情、不发布或提交。

## Acceptance criteria

- [x] 已确认缺陷有修改前失败、修改后通过的回归证据（9 项模型失败及浏览器固定列命中失败）。
- [x] 配置读写保留节点、seed、金额精度和时间语义，短区间预设不再部分应用。
- [x] 非法配置在预览和保存前给出明确反馈，启用中配置沿用先停止再修改的后端规则。
- [x] 聚焦测试、Web 全量 499 项、所有 Web 质量门禁通过；现有实库策略接口 4/4 及浏览器本地读写验证通过。

## Final scope and verification

- 浏览器额外定位“修改”等操作列按钮被固定列裁切，采用仅行情策略生效的整按钮换行；1728px 和 1280px 的按钮边界/实际点击验证通过。
- 实际暂停、节点校验、精确配置保存、V2 回填和 V3 无写入预览已在一次性库核验；未更改后端算法、Seed 策略和版本事务。
- 本地验证环境已全部清理，未提交或部署。具体测试命令和结果见 `docs/superpowers/PROGRESS.md` 本次切片。

## Out of scope

- 不修改行情生成算法、市场价格或真实策略状态；不自动重写历史行情。
- 不改动新币、Mobile 或其他后台业务。
