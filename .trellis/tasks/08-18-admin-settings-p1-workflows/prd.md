# P1 后台配置中心与业务流程重组

## Goal

建立可搜索、可观测的配置中心，明确区分配置、发布、运行与人工处置，并收敛裸 ID 与重复入口。

## Requirements

- 配置中心汇总业务域、状态、最后修改、已应用版本、最近测试和快捷入口。
- 后端提供稳定的配置状态聚合合同，页面不自行猜测运行状态。
- KYC 规则/审核、预测配置/同步运行、管理员个人安全/全局安全政策拆分为明确路由。
- 新币、代理分配、风控对象等主要裸 ID 改为可搜索引用选择器，同时展示状态和关键约束。
- Dashboard 消费已有审计摘要，环境标签来自后端/构建元数据。
- SMTP 统一以具名配置为主入口，兼容单例明确弃用状态，不再出现两个可见写入流程。

## Acceptance Criteria

- [x] 管理员可从配置中心搜索并进入所有主要设置页，状态和跳转有自动化测试。
- [x] 配置任务和运营处置分路由，但保留相互快捷入口和兼容重定向。
- [x] 优先裸 ID 入口无需手工记忆 ID，且失效/禁用引用不可被误提交。
- [x] Dashboard 显示 24 小时管理操作和最近变更，非生产环境不再显示固定“生产环境”。
- [x] SMTP 主流程只有一个写入入口，兼容路径有回归测试。
