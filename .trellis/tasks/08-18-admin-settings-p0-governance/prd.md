# P0 后台权限审计与配置安全治理

## Goal

建立后端强制的管理员 RBAC、完整审计上下文、配置乐观并发控制与高风险变更复核底座，首批覆盖预测配置和贷款产品。

## Requirements

- 权限码作为唯一数据源，后端按路由和动作强制校验，前端仅用于导航与操作可见性。
- 超级管理员保持全权限兼容；非活动账号、缺失角色或缺少权限必须被后端拒绝。
- 统一审计写入包含管理员、原因、来源 IP、request/correlation ID、before/after 和 revision，且不记录密钥明文。
- 配置写入接收客户端 revision，旧 revision 返回 409，不得覆盖新值。
- 预测设置、预测资产配置、贷款产品创建/修改/状态变更必须消费非空原因并写入 before/after 审计。
- 建立通用高风险配置变更申请，制作人与复核人不可相同，状态转换与审计同事务。

## Acceptance Criteria

- [x] 有可执行的权限清单和路由映射测试，无权限写请求返回 403。
- [x] 管理员信息接口返回即时权限，后台隐藏不可达导航和通用资源操作。
- [x] 审计日志可查询真实来源 IP 和 request ID，before/after 不含敏感明文。
- [x] 预测/贷款首批写路径要求原因，具备冲突测试和审计断言。
- [x] 高风险申请禁止自审，拒绝/批准/已应用转换可重放且不产生重复副作用。
- [x] Rust 格式、相关路由测试与后台 typecheck/聚焦测试通过；全仓架构、Clippy、build 随 P1/P2 最终门禁统一执行。

## Out of Scope

- 不在此子任务内一次性把所有低风险 CRUD 迁移成审批发布。
- 不把权限声明仅嵌入 JWT 后长期缓存，避免角色变更后权限仍延迟生效。
