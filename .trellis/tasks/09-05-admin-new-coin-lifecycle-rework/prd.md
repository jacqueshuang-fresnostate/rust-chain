# 重整后台新币业务操作与生命周期

## Goal

将后台新币从分散的通用表单整理为项目中心，统一项目配置、生命周期推进、申购、派发、上市购买及解禁规则，使前后端对每一阶段的业务语义和可操作条件一致。

## What I already know

- 用户明确要求整体整理后台新币逻辑、操作及生命周期，而不只是增加预热转申购按钮。
- 上一切片的快捷操作与路由修复尚未提交，必须保留并纳入新工作流。
- 当前生命周期为 `preheat -> subscription -> distribution -> listed`；启用状态和解禁规则另有字段。
- 实施前审计发现即时申购与后台派发冲突；已完成的资金切片改为冻结后人工派发及退款，历史订单保留旧语义，页面分类现已完成项目中心与五类工作台切片。
- 操作页缺少项目当前配置回填、有效下一步约束、权威刷新和上市后购买配置；`listed_at` 混用计划时间和实际上市时间。

## Assumptions (temporary)

- 先审计所有真实写路径和历史数据合同，再决定阶段重构；不直接修改运行环境的数据。
- 项目生命周期、运营启停与个人锁仓解禁需要明确区分。
- 保留现有不超募的申购准入；接受订单仅预留额度，不承诺最终满额。后台按订单确认最终派发量。

## Open Questions

- 资金切片已确认并实现：后台一次确认最终派发量，零数量全额退款；不增加用户自行撤单或已派发回收。
- 用户已确认“项目中心 + 跨项目处理工作台”及五类菜单，开始实施页面结构与配置回填切片。

## Requirements (evolving)

- 用户明确确认：申购后不自动派发，由后台填写实际派发数量；允许不足申购量，按下单发行价快照扣款并将差额退回原计价资产可用余额。
- 后台确认以单笔申购为最终结算单位，扣款、退款、派发和释放未使用预留供给在同一事务完成；同单不得二次派发或退款。允许零派发全额退款。
- 历史订单显式标为旧模式，不重新冻结或退回已扣款资金；旧订单的既有派发数量上界保留。
- 梳理项目创建与编辑、阶段推进、派发、上市购买、费用和解禁入口。
- 定义阶段/操作矩阵与错误处理、并发、重复操作边界。
- 历史订单、资金流水和锁仓记录不应被新的规则重写。
- 项目中心统一展示当前配置、供给、关联订单和历史；编辑权限与下一步操作由后端权威状态决定，写事务再次校验。
- 明确计划时间/实际事件、上市/现货交易/发行价购买、规则配置/既有锁仓快照的不同边界。
- 校准自动与手动解禁的手续费凭证校验；处理重复操作、状态竞争和结果未知时的重试。
- 公共合同变化同时考虑 Mobile 与 PC，保留既有历史订单的结算语义。

## Confirmed page structure — 2026-09-05

- 项目管理：列表进入单项目中心；配置回填、阶段进度、条件检查和历史整合在项目上下文内。
- 申购与配售：跨项目筛选和处理待派发订单，关联实际派发与差额退款；已结算订单只查看。
- 派发与退款记录：只读查看实际派发、退款及关联流水；额外赠币与申购履约分开标记。
- 锁仓与解禁：仓位和释放记录分标签，规则编辑仍属于项目配置。
- 上市后购买：独立订单类型；购买开关和交易对配置归项目中心，避免与申购混称。
- 独立“生命周期动作”菜单退场；旧深链、项目筛选、审计链接和资源级权限保持兼容。
- 保留四阶段代码，以“开始申购 / 结束申购 / 确认上市”等命令代替任意状态编辑；运营启停、订单结算与个人解禁各自独立。
- 详细页面职责、迁移边界与实施顺序见 `research/page-and-rule-plan.md`。已落地核心页面切片，实际边界及验证见 `project-center-review.md`。

## Decision (ADR-lite)

- 背景：既有申购即时成交与后台后续派发的业务入口不一致。
- 决策：2026-09-05 用户确认分阶段配售方向；申购阶段只冻结，后台一次最终确认原子完成实际获配结算、币的派发和差额退款，不设置单独的“已扣款未派发”中间状态。
- 影响：需要显式区分历史已结算订单与新流程订单，保障冻结资金和供给守恒；用户进一步明确人工确认实际派发量并退差额；不增加超募、抽签或对历史已派发资产回收。
