# Pencil 杠杆确认弹窗审计

## 当前设计基线

Pencil 当前选中的杠杆弹层 `f0L8yf/R8t0p` 与 `aNuw6/PKAcD` 共同确立以下生产语言：

* 内容从手机画布底部上浮，顶部为 22px 圆角与 38×4px 抓手；背景页面使用约 64% 深色遮罩。
* Header 由 19px 粗标题和 44×44 的圆形关闭目标组成，不使用通用卡片式图标标题。
* 数据卡使用 12px 圆角、1px 中性边框、浅色 `#f7f9f8` / 深色 `#070a09` 层级。
* 主要状态使用薄荷绿，风险信息使用低饱和暖橙面板；主按钮为 48px 高的全宽药丸按钮。
* 浅色与深色不是简单反色，而是分别维护页面、画布、抬升层、线条、正文和弱化文字角色。

## 生产现状差距

`TradeView.vue` 当前确认层是现货与杠杆共享的通用 `.confirmation-sheet`：

* Header 仍是 38px 图标加通用“确认”标签，不符合已批准的杠杆弹层标题轨道。
* 仅展示交易对、数量、价格和金额，缺失保证金模式、杠杆倍数、保证金、名义价值、预估数量与市场价风险。
* 全局基础样式使用 2px 青色顶边和方形双按钮，视觉上与已完成的杠杆倍数/模式弹层断裂。
* 接口提交失败后错误写在页面主体，遮罩仍打开时用户看不到错误。
* 确认层未 Teleport 到 `body`，存在被路由或页面层叠上下文约束的风险。

## 收敛方案

采用“同一确认状态、按交易模式分支呈现”的方案：

* 保留 `TradeView` 当前真实订单校验、提交函数和可访问性状态机。
* 只为杠杆模式增加专属内容与 scoped 样式；现货内容不重构。
* 将整个确认层 Teleport 到 `body`，通过模式类区分现货与杠杆。
* 杠杆面板使用与 `ContractTradeSheets` 相同的视觉令牌和安全区行为，增加可滚动明细区及固定操作区。
* 将现有 `feedback` 错误同步显示在打开的杠杆确认面板中，不改变 API 错误映射。

这样可以修复用户指出的视觉断层，同时将改动限制在手机端确认体验，不触碰后端业务。
