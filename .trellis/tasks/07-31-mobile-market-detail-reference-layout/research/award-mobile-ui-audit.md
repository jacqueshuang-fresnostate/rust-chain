## 可迁移设计规律

### Awwwards / Wise / Recent

- 每屏只有一个视觉主角：大标题、主数据或主操作，不把所有模块都做成同等权重的卡片。
- 通过极大的字号差、留白和不对称排版建立节奏，装饰仅服务于主叙事。
- 单一高饱和品牌色负责主动作和品牌记忆，其他状态色保持克制。
- 移动端首屏通常只有一个全宽主按钮、一个强内容块和极简 Header；低频入口退居次级层级。

### Linear

- 近黑画布、白色主文字、发丝分隔线和极少量边缘辉光比大量渐变卡片更显精密。
- 产品界面作为一个连续舞台展示，而不是拆成许多互相独立的圆角卡片。
- 微型控制件在半径、描边、图标尺寸和反馈上完全一致。

### Coinbase Advanced / OKX

- 交易页应边到边、平面化、数据优先：价格、三项关键统计、图表、订单簿或表单构成连续工作台。
- 图表是交易首屏的视觉主角，圆角和阴影应少于发现型页面。
- 订单簿、成交、订单与仓位使用紧凑标签和发丝分隔线，不使用大卡片间距。
- 买卖主动作使用单一语义色，其他工具保持中性，避免每个按钮都争夺注意力。

## 不直接复制的部分

- 不复制竞品品牌、专有插画、宣传文案、资产、色板或无后端支持的功能。
- 不增加虚假收藏、预警、策略、杠杆、排名或收益数据。
- 不牺牲真实 API、WebSocket、PWA/Tauri/Android、Lucide 图标、键盘操作、44px 触控和双语合同。

## 本地页面审计

审计截图位于 `research/screenshots/award-audit/`。390px 视口下关键页面均无文档横向溢出，但存在明显的视觉系统和密度问题。

### 全局外壳

- Root Header 的金属 Logo 与拟物圆形按钮已经形成识别度，但正文同时使用方框、圆形、软圆角、硬描边等多套材质，缺少统一规则。
- 七项底部导航在 390px 内全部可用，但信息密度过高；中央秒合约凸起过强，长期抢占每个页面的主视觉。
- 背景网格、信号曲线、卡片描边、圆形轨道和大色块经常同时出现，装饰层之间相互竞争。
- 明亮模式的灰蓝画布和大量浅灰字使二级页面显得褪色；暗色模式更统一，但部分页面仍有过多边框。
- 顶层页面与二级页面缺少一致的标题、状态、空态、表单和按钮语法。

### 首页

- 390px 首屏存在约 37 个可见交互目标，工具矩阵、资产图、两个主按钮、公告和七项导航同时争夺注意力。
- 访客状态下资产 Hero 占据大量纵向空间却只有遮罩数值，视觉产出低。
- 珊瑚公告卡比买币/充币和核心行情更抢眼，主次倒置。
- 资产曲线、网格、按钮和工具圆环的线条语言不统一。

### 行情列表

- 鲜明的绿色 Editorial Hero 是当前最有辨识度的部分，应保留但压缩高度并让搜索/分类紧密衔接。
- 390px 视口中约 46 个交互目标；页面同时有顶部筛选、搜索、分类、情绪指数和榜单，控制层级偏多。
- 数据只有少量行时，下方大面积空白，列表缺乏连续行情终端的结构感。
- 情绪指数卡使用亮白底，暗色主题中割裂画布。

### 现货交易工作台

- 暗色模式的边到边图表与紧凑报价已接近专业交易质感。
- Root Header、交易对 Header、周期栏、图表、委托标题和底部导航在一个首屏中层级过多；需要让交易对/价格成为唯一首屏主角。
- 输入控件的实际内部输入高度约 18px，依赖外层容器补足触控；聚焦、禁用和主题材质应由统一控件合同管理。
- 周期、指标、刷新、设置的工具语法还不完全一致。

### 资产

- 大型绿色 Hero 和轨道图形有品牌感，但总资产、四个快捷动作和分布区域之间纵向间距偏松。
- 深色主题比明亮主题更完整；明亮主题需要更纯净的白、石墨文字和更清晰的分隔。
- 资产分布空数据仍展示完整图例和大面积骨架，访客状态应更诚实地压缩为登录引导。

### 我的

- 访客页有效内容很少，却保留大面积背景网格与空白，首屏视觉密度失衡。
- 登录与注册按钮权重接近但材质不一致，注册按钮灰度类似禁用态。
- 语言与客服入口过于细小、发灰，缺少可扫描的分组和状态提示。

### 消息中心

- 空状态页面使用大量灰色描边和低对比文案；筛选区占据的视觉重量大于消息本身。
- 统计、分类、未读过滤和批量处理同时出现，但空数据时不应全部维持最大展开状态。
- 返回/刷新 Header 已可用，需要与安全中心、借贷等二级页面共用同一标题与动作语法。

### 借贷

- 当前空数据仍显示两张几乎相同、充满 `--` 的产品卡，看起来像失效 Demo，而不是受后台控制的真实空态。
- 摘要、产品、我的借款和历史订单均使用同等描边，缺少任务路径。
- 应以“可借额度/产品状态”为主舞台，有数据时展示产品，无数据时直接展示清晰的后台控制说明和刷新动作。

### 安全中心

- 信息结构完整，但 390px 下连续发丝框、图标框、说明框和输入/开关形成过度网格化。
- 多个输入本体高度约 36px，需统一到可见 44–52px 控件高度，而不只依赖外层。
- 未登录状态仍展开所有设置细节并显示 `--`，应先展示安全状态和登录引导，再渐进披露配置。

### 登录与产品二级页

- 登录页的信息路径清楚，但 Logo、步骤 Header、表单和底部注册链接之间留白过大；输入使用灰蓝填充，明亮模式仍显沉闷。
- 产品中心使用分组编号和网格，结构合理；核心资金服务与市场工具卡的图标容器、描边和强调色不一致，需要收敛为同一 Instrument plate。
- 理财、充币等未登录页只显示一张登录卡并留下大面积空白；应让空态本身成为紧凑、明确的主舞台，而不是页面顶部的一条弱提示。
- 新币与预测页重复“产品说明卡 + 空状态 + 登录卡”三层结构，视觉冗余；应合并成一个真实状态面板并保留登录动作。

## 目标方向：HIPPO Instrument Editorial

### 三层材质

1. **Canvas**：明亮模式使用清透冷白，暗色使用近黑石墨；背景信号纹理只在一个局部区域低透明出现。
2. **Instrument plate**：交易、表格和二级页面用平面化发丝分隔；Hero/发现页才使用 16–24px 大圆角或异形裁切。
3. **Primary action**：高饱和薄荷绿只用于主操作、当前状态和少量品牌光；珊瑚只用于风险/跌幅/重要提醒。

### 排版与几何

- 每页只设一个视觉主角：一个主数值、主标题或主动作。
- Hero 28–36px；页面标题 20–24px；区块标题 16–20px；标签 11–12px；仅数字使用等宽字。
- 数据表/交易区半径 0–4px；Editorial Hero 半径 16–24px；Header 图标控制固定为 44px 圆形。
- 顶层页面保留品牌 Editorial，交易/表单/数据页转为连续工作台。

### 色彩

- Light：清透白/冷白 + 近黑石墨 + 薄荷绿主色；避免大面积灰蓝蒙层和低对比灰字。
- Dark：`#08090a` 级近黑 + 冷白 + 薄荷绿；只在边缘使用极少量光泽。
- 珊瑚和蓝色分别保留给风险/跌幅和信息状态，不能作为随机装饰。

### 动效

- 首次进入仅对视觉主角做一次 350–650ms 的错峰进入；数据、表单和固定导航不做永久漂浮。
- 路由过渡只承担方向感，不能长时间保留上一页或遮住可交互内容。
- `prefers-reduced-motion` 下取消位移和物理回弹，保留必要的透明度反馈。

## 实施优先级

1. 统一全局色彩 token、Header、底部异形导航、按钮/输入/弹窗/空态和背景纹理。
2. 重排首页：减少首屏竞争，强化一个资产/市场主舞台，压低公告与工具权重。
3. 优化行情列表：压缩 Hero、合并筛选层、强化连续行情列表。
4. 收敛现货/合约/秒合约的交易工具语言，不改变请求和订单行为。
5. 优化资产与我的访客/登录状态。
6. 将消息、借贷、安全中心及其他二级页迁移到共享 PageShell、状态板、表单和空态系统。

## 实施后 Ego 验收

- 根页面：首页、行情、现货、资产、我的在 320×720、360×800、390×844、448×900 的明暗主题共 40 组检查中，文档横向溢出均为 0，首屏可见交互目标均不小于 44px。
- 七项底部导航的中央命中点在所有根页面均由 `.bottom-nav` 或其子项承接；路由进场类延迟清除时不再由正文/订单簿截获点击。
- 320px 现货长价格保持单行，`white-space: nowrap` 且内容宽度不超出容器；订单簿 split 布局仍可读。
- 行情搜索输入本体为 44px，输入本体无 border/outline，外层只显示一个完整 focus border/ring；交易表单输入为 44px、字段容器为 52px，使用相同聚焦语法。
- 消息、借贷、安全、登录和产品中心在 320/390/448px 明暗主题下无横向溢出，首屏可见交互目标均不小于 44px。
- `prefers-reduced-motion: reduce` 下路由动画为 0、幕帘隐藏、滚动为 `auto`，交易按钮过渡降至最小且没有页面位移。
- 底栏实际点击已验证：首页 → 行情、现货、合约、资产、我的、秒合约分别进入对应真实路由，现货与合约保持独立。
- Ego 事件队列最终无 console error、exception 或失败事件。
- 代表性实施前后截图保存在 `research/screenshots/award-audit/`。
