# 手机端 UI 对齐原型重构

## 背景

`mobile/sites-prototype/` 已完成并确认了 HIPPO 手机端的视觉原型，但真实 Vue 客户端 `mobile/src/` 仍大量使用通用后台式页面：居中标题、孤立圆角卡片、过大的留白和弱化的信息层级。当前真实端虽然已经接通后端接口、认证状态和 PWA，但页面样式与原型不一致，尤其在订单、交易、资产和二级页面中差异明显。

本任务以已确认的 Sites 原型为视觉合同，把真实客户端重构为同一套设计语言，同时保留所有真实业务接口、校验、状态管理、路由和 PWA 能力。

## 目标

- 让真实 Vue 手机端在共享壳、核心页面和二级页面上与 `mobile/sites-prototype/` 的视觉层级、间距、边界、排版和交互形态一致。
- 统一浅色与深色设计令牌，浅色模式保持明亮、高对比和冷中性色，不使用旧的 `#0b1811` 色系。
- 保持现货、合约、秒合约为独立栏目，异形七栏底部导航保持稳定且不遮挡内容。
- 统一 Header、输入框、按钮、标签页、列表、状态卡、弹窗和底部面板的外观与焦点状态。
- 完整覆盖真实端全部 36 个路由对应页面，不再让二级页面停留在简单表单或空白状态。
- 保留已经接通的后端 API、鉴权、错误处理、加载状态、业务校验、PWA 和 Tauri 能力。

## 视觉方向

- 参考原型中的 “Signal Theatre” 交易终端语言：高密度数据、硬边界、精确网格、非对称信息层级与克制动效。
- 手机内页以紧凑工作台为主，不复制原型桌面展示舞台，也不引入营销落地页。
- 使用 0 至 8px 的小圆角，避免大面积胶囊和卡片套卡片。
- Lucide 为唯一图标来源，界面禁止表情符号和手绘 SVG 图标。
- 标题、数字、标签和辅助文本形成明确的字号与字重梯度；不按视口缩放字体，不使用负字距。
- 操作按钮必须有清晰的主次关系、按压状态、禁用状态、加载状态和焦点可见状态。
- 输入框聚焦使用容器级 `focus-within` 边界，禁止浏览器原生蓝色内框破坏组合输入布局。

## 功能范围

### 1. 共享壳与设计系统

- 重构 `base.css` 中的浅色/深色令牌、页面背景、表面、边线、文本、正负色、强调色、阴影、圆角和动效。
- 重构 `App.vue`、`PageHeader.vue`、`AppBottomNav.vue`、登录状态、PWA 状态以及可复用图表/盘口/资产图标组件。
- Header 在滚动和路由切换期间保持不透明并位于内容之上；一级页面品牌 Header 与二级页面左对齐信息 Header 分工明确。
- 底部导航为稳定异形结构，中间秒合约入口抬升；320px 宽度下七项文本和图标仍不重叠。

### 2. 一级核心页面

- 首页对齐原型的品牌 Header、搜索、资产总览、收益信号、快捷操作、产品入口、市场表格和资讯层级。
- 行情页采用紧凑市场工作台，保留真实搜索、分类和交易对跳转。
- 现货与合约继续复用真实交易逻辑，但视觉上明确区分模式，重构行情头、图表、盘口、订单面板、数量/价格输入和操作区。
- 秒合约使用独立的高冲击交易仪表盘，不与现货或合约合并；保留产品周期、方向、金额和真实订单状态。
- 资产页重构总资产、操作矩阵、账户分组、资产列表和空状态。
- 我的页面重构身份区域、账户等级、统计指标和功能矩阵。

### 3. 订单与业务二级页面

- 订单中心采用原型中的左对齐标题、三栏标签、紧凑订单/持仓列表和明确批量操作，不再出现大面积空白。
- 消息中心重构分类、未读状态、消息列表、详情反馈和空状态。
- 借贷、理财、新币、预测、闪兑采用一致但具业务差异的产品工作台、资产输入、收益/风险信息和操作反馈。
- 安全中心、身份认证、账号绑定、推荐、语言、账单采用结构化设置分组和明确状态层级。
- 登录、注册、忘记密码、二次验证采用统一品牌认证壳和高质量表单。
- 充值、提现、快捷充值、网络选择、记录和新闻相关页面全部对齐共享二级页面语法。

### 4. 响应式与可访问性

- 必须在 320px、390px、448px 三种手机宽度验证主要页面。
- 固定工具栏、标签页、底部导航、数字列和图标按钮使用稳定尺寸，动态内容不得引发布局位移。
- 图标按钮至少 44x44px，含明确 `aria-label`；文本和按钮不得溢出或互相遮挡。
- 支持 `prefers-reduced-motion`，所有动效不阻塞操作。
- 浅色、深色均满足清晰对比，输入聚焦、错误、成功、加载和禁用状态可辨识。

## 业务约束

- 不复制原型中的模拟余额、模拟订单、用户名或静态市场结果。
- 所有真实页面继续使用现有 API、Pinia store、i18n 文案、路由名和登录重定向。
- 不修改后端接口语义，不绕过认证，不降低表单校验或交易确认。
- 用户未登录时继续展示真实登录要求；有数据、无数据、加载、错误和成功状态均必须有完整设计。
- PWA manifest、service worker、离线状态和 Tauri 构建保持可用。

## 非目标

- 不修改 PC 端页面。
- 不改动后端领域逻辑或数据库。
- 不把 Sites 原型 React 组件直接复制到 Vue，也不把模拟数据带入生产客户端。
- 不新增 Web3 钱包栏目。
- 不将现货和合约合并为同一导航栏目。

## 实施分组

### Slice A：基础与一级体验

- 共享设计令牌、App 壳、Header、底部导航和通用状态组件。
- 首页、行情、资产、我的、产品中心。

### Slice B：交易域

- 现货、合约、秒合约、市场详情、订单中心。
- 图表、盘口、交易输入、确认弹窗和订单/持仓状态。

### Slice C：完整二级页面

- 消息、安全、KYC、绑定、借贷、理财、新币、预测、闪兑、认证、推荐、账单、充提、新闻等剩余页面。
- 复用 Slice A 的设计令牌，不单独发明视觉系统。

## 验收标准

- [x] 共享壳、一级页面和全部二级页面与 `mobile/sites-prototype/` 使用同一套视觉语法，真实端不再呈现通用后台模板感。
- [x] 首页、行情、现货、合约、秒合约、资产、我的七个一级入口在 320/390/448px 下无重叠、截断或底部导航遮挡。
- [x] 现货、合约、秒合约保持独立栏目和独立视觉状态。
- [x] 订单中心登录态与未登录态均完整；标签、订单、持仓、历史、批量操作和空状态层级清晰。
- [x] 消息中心、借贷、安全中心及其余二级页面均具有完整的页面结构、表单和业务状态设计。
- [x] 浅色模式明亮且高对比，不出现 `#0b1811`；深色模式保持独立且输入/按钮/弹窗样式一致。
- [x] 组合输入框聚焦时无原生内层蓝框，错误和成功状态不会改变布局尺寸。
- [x] Header 在滚动与路由动画期间不被内容覆盖；异形底部导航稳定且中间秒合约入口居中。
- [x] Lucide 为唯一图标来源，生产界面没有表情符号。
- [x] 真实后端 API、认证、Pinia、i18n、路由、PWA 和 Tauri 行为无回归。
- [x] `npm --prefix mobile run type-check`、`npm --prefix mobile test`、PWA 构建和 Tauri 构建通过。
- [x] 使用浏览器对核心路由执行 320/390/448px 视觉验收，并检查控制台错误和画布/图表非空。

## Definition of Done

- 三个实施切片完成并通过独立检查。
- 最贴近改动的类型检查、测试、构建和浏览器验收通过。
- 更新 `.trellis/spec/mobile/` 中可复用的视觉交付规范。
- 更新 `docs/superpowers/PROGRESS.md`。
- 任务提交、归档并记录开发日志。
