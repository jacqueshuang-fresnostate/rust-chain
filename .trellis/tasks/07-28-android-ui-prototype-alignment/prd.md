# 安卓端 UI 与公开原型逐页对齐

## 背景

公开原型 `https://hippo-mobile-signal-2026.ikuboy.chatgpt.site/?version=16`
已经确定了 HIPPO 手机端的最终设计方向。真实客户端 `mobile/src/` 虽然已经接入
后端、认证、行情、交易、PWA 和 Tauri，但当前实现只迁移了部分信息结构和通用
设计语言，没有与原型一一对应。

2026-07-28 的 390x844 同屏审计显示：

- 原型为高亮纸面式浅色工作台，使用精细网格、荧光绿资产曲线、橙色信号面、
  左对齐品牌 Header、圆形工具按钮和雕刻式异形底部导航。
- 真实端仍使用居中小 Logo、黑色资产大块、普通搜索框、简单产品宫格和近似
  异形导航，首屏结构、尺寸、色彩、密度和动势均不一致。
- 浏览器中的 `mobile/src` 与 Android Tauri 共用同一套 Vue 源码，因此应在
  `mobile/src` 修复视觉层，并用真实 Android APK 构建验证资源已同步。

## 目标

- 以公开原型版本 16 为唯一视觉基准，重构 Android/H5/PWA 共用的 `mobile/src`。
- 逐页对应原型的布局、视觉令牌、组件形态、层级、交互状态和响应式行为。
- 保留所有真实 API、Pinia store、认证、交易校验、路由、i18n、PWA 和 Tauri
  行为，不引入原型的模拟账户或模拟交易副作用。
- 重新构建 Android Debug APK，确认 APK 内是本次 UI 而非旧前端资源。

## 视觉合同

### 浅色模式

- 页面底色为近白纸面，主表面为白色，网格线和边界使用冷中性灰。
- 文本为近黑色，正向/主信号使用高亮绿色，强调与风险使用橙红色，辅助数据可
  使用蓝色。
- 首页资产区必须是原型的明亮资产总览，而不是当前黑色大面板。
- Header 左侧显示官方 HIPPO 横向 Logo，右侧使用两个独立圆形工具按钮和未读
  信号点；搜索与扫码工具在 Header 下形成独立工具行。
- 页面背景使用低对比网格与细线，不使用模糊渐变球或大面积暗淡灰色。

### 深色模式

- 保留原型独立的深色令牌，不对浅色页面进行简单反色。
- 输入、按钮、弹层、行情、图表、秒合约和异形导航必须保持相同结构与尺寸。

### 共享组件

- Lucide 为唯一图标来源，禁止表情符号和手绘 SVG 图标。
- 图标按钮至少 44x44px；圆形工具按钮的 SVG 必须双轴居中。
- 输入焦点属于完整字段容器，内部 input 不显示第二层蓝色边框。
- 主按钮、次按钮、危险按钮、标签、筛选、错误、成功、加载和禁用状态尺寸稳定。
- 圆角以 0 至 8px 为主；圆形只用于图标按钮、币种标记和抬升的秒合约入口。
- Header 为不透明 sticky 层，路由过渡和滚动内容不得覆盖 Header。
- 底部导航保持七栏：首页、行情、现货、秒合约、合约、资产、我的；秒合约为
  居中的抬升异形入口。

## 页面范围

### Slice A：壳层与一级页面

- `App.vue`、`base.css`、`PageHeader`、`AppBottomNav`、`PwaStatus`、
  `LoginRequiredState` 和资产/品牌视觉组件。
- 首页对齐原型品牌 Header、搜索/扫码工具行、资产收益面板、买币/充币、八项
  产品入口、橙色行情日报、五类行情表、任务与安全入口。
- 行情页对齐原型的标题、搜索、分类、市场温度和高密度行情列表。
- 资产页对齐资产 Hero、资产分配、资金动作和账户列表。
- 我的页对齐身份 Hero、等级、指标和设置入口。
- 产品中心保持完整真实路由，但采用原型业务矩阵层级。

### Slice B：交易域

- 现货、合约、秒合约继续保持三个独立主栏目。
- 现货/合约对齐原型行情头、报价、图表、盘口、买卖切换、订单类型、完整字段、
  比例选择、手续费/保证金摘要、订单确认和登录态。
- 秒合约对齐原型的独立市场仪表板、周期、方向、金额预设、派彩、余额、确认、
  会话反馈和订单记录。
- 市场详情与订单中心对齐二级 Header、标签、数据密度和操作面。

### Slice C：二级页面

- 消息、借贷、安全、KYC、绑定、认证、推荐、语言、理财、新币、预测、闪兑、
  钱包、账单、充提、记录和新闻页面统一使用原型二级页面语法。
- 不允许只改变颜色而保留大面积空白、孤立通用卡片或默认浏览器表单。
- 每个页面必须设计未登录、加载、错误、空、成功、禁用和提交中状态。

## 业务约束

- 不修改后端接口路径、请求载荷、响应适配器或鉴权刷新语义。
- 不复制原型中的静态资产余额、用户名、订单、持仓或金融结果。
- 真实数据不可用时展示真实错误/空/登录状态，不伪造成功。
- 不新增 Web3 钱包。
- 不将现货、合约、秒合约合并。
- PWA 不缓存 API、认证、WebSocket 或金融响应；Tauri 构建不包含 PWA 工件。
- Android 发布构建必须使用设备可访问的 HTTPS 后端域名，禁止 loopback 回退。

## 响应式与可访问性

- 390x844 为主要视觉验收尺寸。
- 320x720 与 448x900 必须无横向溢出、文字遮挡、Header 覆盖或导航遮挡。
- 数字列、按钮、标签、图表、订单簿和弹层必须使用稳定尺寸。
- 支持 `prefers-reduced-motion`。
- 所有图标按钮有可访问名称，标签选择状态使用 `aria-selected` 或
  `aria-pressed`。

- [x] 行情、现货、合约、秒合约、资产、我的与对应原型页面使用同一视觉合同。
- [x] 消息、借贷、安全和其余二级路由不再保留通用后台模板感。
- [x] 现货、合约、秒合约保持独立栏目和独立路由。
- [x] 浅色模式明亮、高对比；深色模式结构一致；输入焦点无双层边框。
- [x] 320px、390px、448px 核心页面无溢出、重叠或底部导航遮挡。
- [x] 真实 API、Pinia、鉴权、i18n、交易校验、PWA 和 Tauri 行为无回归。

- [x] `npm --prefix mobile run build:pwa` 与 `npm --prefix mobile run build:tauri`
      通过，Tauri 产物不含 PWA 工件。
- [x] Android Debug APK 成功重建，并确认生成时间与本次代码一致。
- [x] 浏览器完成核心页面三档宽度截图和控制台检查。

## 非目标

- 不修改 PC 端、后台或 Rust 后端领域逻辑。
- 不重新设计公开 Sites 原型。
- 不增加与本次视觉对齐无关的新业务功能。
