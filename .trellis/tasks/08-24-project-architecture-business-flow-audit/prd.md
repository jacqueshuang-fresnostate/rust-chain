# 全项目结构与业务流程优化审计

## Goal

对当前单仓库中的 Rust 后端、管理后台、PC 端、手机端、数据库迁移、消息队列/后台任务、实时行情、测试、CI 和部署进行全面静态审计，用可定位的代码证据识别结构性技术债与业务流程缺口，形成可分批执行的 P0/P1/P2 优化路线图。

## What I already know

- 项目是单仓库，包含 Rust API/工作器、`admin`、`pc`、`mobile` 与多组迁移/部署配置。
- 业务覆盖账户/资产、现货、杠杆、秒合约、闪兑、借贷、理财、预测、新币、代理、客服、KYC 和管理配置。
- 当前 Trellis 存在大量长期 `in_progress` 任务，任务状态本身也是交付治理的审计对象。
- 工作区已有其他未提交改动；本审计只新增审计文档/任务记录，不覆盖或整理既有业务改动。

## Requirements

1. 盘点根目录、应用边界、后端模块、工作器、迁移、前端路由/API 层、测试和部署资产。
2. 量化过大文件/函数、重复实现、跨层依赖、配置分散、长期任务和测试/构建缺口。
3. 按“请求 → 应用服务 → 领域规则 → 账本/订单 → outbox/MQ → 读模型/私有 WS → 前端状态”检查核心资金流。
4. 覆盖注册与钱包初始化、充提、现货成交、杠杆开/平仓与强平、秒合约结算、闪兑、借贷、理财、预测/新币、客服/代理归属等业务流。
5. 每条重要发现必须包含：问题、可观测证据、影响、建议方案、验收方式、估算与前置依赖。
6. 优先级定义：P0=可造成资金/权限/数据正确性风险；P1=明显影响可维护性、可用性或交付效率；P2=一致性、体验、性能与治理改进。
7. 输出一份仓库内可持续更新的审计报告，并给出 30/60/90 天实施顺序。

## Acceptance Criteria

- [x] 报告覆盖后端、三端前端、数据、异步/实时、测试和部署。
- [x] 报告含项目结构现状图、目标边界、业务流程风险图和 P0/P1/P2 清单。
- [x] 所有 P0/P1 发现都有仓库路径与行号/符号证据，不使用无证据猜测。
- [x] 区分“已实现但需重构”、“流程不完整”、“没有自动验证”三类问题。
- [x] 优化建议不要求一次性重写，可以独立任务切片执行。
- [x] 审计文档 Markdown 链接/路径有效，Trellis context validate 与 `git diff --check` 通过。

## Definition of Done

- 完成基于源码、迁移、测试和部署文件的静态审计。
- 新增 `docs/architecture/project-optimization-audit-2026-08-24.md`。
- 审计中不执行会写入生产数据、提交订单、创建用户或改变远程环境的操作。
- 完成审计文档的证据复核与进度记录。

## Technical Approach

1. 先用文件/依赖/规模统计建立仓库地图。
2. 分域审查后端架构、核心业务流、前端契约、数据/异步/部署，研究结果写入任务 `research/`。
3. 对高风险发现再做符号调用关系、迁移约束与测试覆盖的交叉复核。
4. 按“先守住资金与权限不变式，再拆边界，最后统一交互/工程”给出增量路线。

## Decision (ADR-lite)

**Context**：仓库业务面广且已有并行未提交工作，直接大规模重构会混入其他任务并增加回归风险。

**Decision**：本任务只交付有证据的审计报告与分期路线图；实际重构后续按独立 Trellis 任务逐项实施。

**Consequences**：本轮可以快速建立统一优先级与依赖关系，但不会在审计完成时自动消除已发现的技术债。

## Out of Scope

- 不在本任务中大规模移动模块、修改数据表或改变资金计算。
- 不连接远程生产数据库，不使用真实账户执行写操作。
- 不重复设计手机 UI，仅审查其模块边界、数据流、错误处理和测试结构。
